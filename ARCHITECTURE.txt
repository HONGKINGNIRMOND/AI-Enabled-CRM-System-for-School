PROJECT ARCHITECTURE OVERVIEW

The School CRM System follows a modern decoupled architecture with a clear separation between the frontend, backend, and database layers.

I. ARCHITECTURE DIAGRAM (Conceptual)

[User] <--> [Frontend: React/Vite] <--> [Backend: Node.js/Express] <--> [Database: PostgreSQL]
                                        |
                                        +--> [Email Service: Nodemailer]
                                        +--> [SMS Service: Twilio]

II. ARCHITECTURE LAYERS

1. Client Layer (Frontend):
   - Framework: React 19 (Vite)
   - Styling: Tailwind CSS
   - Routing: React Router DOM v7
   - Library: Axios (API), Recharts (Graphs), Lucide (Icons)

2. API Layer (Backend):
   - Runtime: Node.js / Express.js
   - ORM: Sequelize (PostgreSQL)
   - Auth: JWT & bcryptjs
   - Utils: Joi (Validation), Multer (Uploads), Winston (Logging), Node-cron (Jobs)

3. Data Layer:
   - Database: PostgreSQL
   - Scripts: backend/scripts for migrations

III. DIRECTORY STRUCTURE

/root
  /frontend - UI and client logic
  /backend  - API, Controllers, and Models
  /database - SQL schema files

IV. CORE WORKFLOWS

1. Authentication:
   Credentials -> Backend -> Password Verify -> JWT Issued -> Frontend Storage.

2. Adding Data (Student Example):
   Form Submit -> Frontend Validation -> Authenticated API Call -> Backend Middleware (Auth/RBAC) -> Logic (Controller) -> DB Persistence (Sequelize) -> Parent Notification.

3. Bulk Data Upload:
   File Upload -> Backend Parse (CSV/XLSX) -> DB Transaction Start -> Batch Import -> Transaction Commit -> result Report.
